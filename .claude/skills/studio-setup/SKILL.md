# 카테고리 맞춤 규칙 만들기

인자: `$ARGUMENTS` (예: `data/setup`). 이하 SETUP. 처음 설정에서 한 번 실행하고, 사용자가 "맞춤 규칙 다시 만들기"를 누르면 다시 실행한다. **`brand/`에 예전 파일이 있어도 참고하지 말고 처음부터 새로 써서 덮어쓴다**(예전 설정 값이 남지 않게). 여기서 만드는 파일이 이후 모든 스킬(주제·리서치·초안·SNS·뉴스레터)의 기준이 되므로, 이 분야에서 실제로 글을 잘 쓰는 사람이 지키는 규칙처럼 구체적으로 쓴다. 일반론("독자를 생각하라")은 쓰지 않는다.

## 0. 읽기

1. `SETUP/input.json`
   - `category`: 분야 이름 (예: "AI·업무 자동화")
   - `groups`: 세부 분야 1~4개. 주제 후보를 고르게 나누는 기준이다.
   - `audience`: 독자
   - `angle`: 사용자가 정한 관점·차별점 (비어 있을 수 있다)
   - `voice`: 말투 (예: "평서체(~다). 칼럼처럼 담백하게")
   - `noEllipsis`: true면 말줄임표를 쓰지 않는다
   - `characterName`: 글쓴이(캐릭터) 이름. 실명이 아니다.
   - `samples`: 문체 샘플 수. 1 이상이면 `brand/corpus/`에 사용자의 예전 글이 있다.
   - `channels`: 블로그·인스타그램·쓰레드는 **항상 만든다.** `instagramHandle`은 카드 아래에 적는 계정 이름일 뿐이라 비어 있어도 인스타그램 규칙을 빼지 않는다. `newsletter`는 구독 안내 줄을 넣을지만 정한다.
   - `today`
2. `samples`가 1 이상이면 `brand/corpus/index.json`과 샘플 글을 모두 읽는다.

## 1. 이 분야 조사 (WebSearch, 필요하면 WebFetch)

검색은 10회 안팎으로 끝낸다. 찾을 것:

- **믿을 만한 출처**: 이 분야의 공식 기관·공식 문서·1차 자료(발표, 공식 블로그, 통계, 원문), 신뢰받는 전문 매체. 한국어와 영어 모두. 출처마다 무엇을 확인할 때 쓰는지.
- **저작권과 이용 조건**: 이 분야에서 사진·영상·자료를 쓸 때 조심할 점(예: 언론사 사진, 유료 기사, 제품 이미지). AI 이용을 금지하는 출처가 있으면 금지 목록에 넣는다(예: 연합뉴스 기사, 네이버 검색 API).
- **위험한 표현**: 이 분야에서 법·윤리 문제가 되는 표현(예: 의료 효과 단정, 투자 권유, 미확인 루머, 개인 사생활).
- **요즘 흐름**: 이 분야에서 지금 독자가 많이 찾는 주제 유형과, 검색으로 오래 읽히는 정보 정리 글의 유형.
- **잘되는 글의 형식**: 이 분야 상위 블로그·인스타 계정이 자주 쓰는 제목 틀과 글 뼈대.

## 2. 문체 샘플 분석 (`samples`가 1 이상일 때)

샘플 글에서 실제로 센 값으로 규칙을 만든다. 문장을 옮겨 적지 않는다.

- 화자와 줄 끝(~다/~요/~습니다), 한 줄 길이(중앙값), 문단당 줄 수
- 자주 쓰는 연결어(하지만, 사실, 물론 등)의 글당 횟수 → "초안 기준" 범위로
- 도입 방식(장면, 질문, 전제), 마무리 방식(질문, 한 줄 요약, 다짐)
- 숫자·근거를 다루는 방식, 이모지·감탄사 사용
- 샘플이 사용자의 `voice` 선택과 다르면 샘플을 따른다.

샘플이 없으면 `voice`와 1장의 조사 결과로 기준을 정하고, 문서 첫머리에 "샘플 없이 만든 기본 기준이며, 글이 쌓이면 피드백으로 고쳐 나간다"고 적는다.

## 3. 출력 파일 (모두 `brand/` 아래)

모든 문서는 한국어로, 표와 짧은 목록 위주로 쓴다. 문서 안에 `{{NEWSLETTER_URL}}`, `{{BLOG_URL}}`처럼 프로그램이 채우는 자리 표시자는 그대로 둔다.

### 3-1. `brand/pillars.json` — 콘텐츠 기둥 4~6개

```json
[
  {"id": "explainer", "name": "독자가 바로 알아듣는 이름", "what": "무엇을 쓰는 기둥인지 한 줄", "format": "해설형", "length": "1,500~2,300자"}
]
```

- `id`는 영어 소문자와 밑줄만. `format`은 해설형·정리형·실용형(따라 하기)·후기형·이야기형·기록형 중에서.
- 기둥 중 하나는 **검색으로 오래 읽히는 정보 정리**, 하나는 **최근 1~2주 이슈**, 하나는 가볍게 읽는 **이야기형**이 되게 한다.
- `length`는 형식에 맞는 분량 범위.

### 3-2. `brand/brand.md` — 브랜드 설정

```
# 브랜드 설정

캐릭터 이름은 설정 화면의 이름이 기준이다. 스킬은 입력 파일의 `characterName`을 쓴다.

## 포지셔닝
- 한 줄: (이 분야를 누구의 언어로 들려주는가)
- 화자: (characterName이 어떤 사람으로 말하는가. 사용자가 적지 않은 경력·경험은 지어내지 않는다)
- 차별점: (angle을 구체적인 글쓰기 장치로. 예: 모든 해설 글에 "쉽게 말하면" 비유 한 개)
- 익명 원칙: 실명, 얼굴, 직장은 어디에도 쓰지 않는다.
- 주제 우선순위: ① … ② … ③ 검색으로 오래 읽히는 정보 정리

## 세부 분야
(groups 각각이 무엇을 다루는지 한 줄씩)

## 콘텐츠 기둥
(pillars.json과 같은 내용을 표로: id | 이름 | 무엇을 | 형식)

## 독자
(audience를 2~3가지 구체적인 독자 모습으로)

## 비유 규칙 ("쉽게 말하면")
(독자가 이미 아는 것에 빗대 설명하는 방법. 무엇에 빗대면 좋은지 예시 3개, 닮은 점과 다른 점을 함께 쓴다는 원칙)

## 금지
(이 분야에서 쓰지 않는 것: 위험한 표현, 확인되지 않은 소문, 사생활 추측 등)
```

### 3-3. `brand/style-guide.md` — 문체 가이드

아래 장 번호를 지킨다(다른 스킬이 장 번호로 참조한다).

1. 화자와 톤
2. 문장과 줄바꿈 (한 줄 길이, 문단당 줄 수)
3. 연결어와 부호 — 표로 "초안 기준" 범위. `noEllipsis`가 true면 말줄임표는 **쓰지 않는다**로 적는다.
4. 숫자와 근거를 다루는 법 — 출처 없는 숫자는 쓰지 않는다. 숫자는 뜻을 해석해 준다.
5. 글의 뼈대 — 형식별(해설형·정리형·실용형·이야기형 등) 도입 → 본문 → 마무리. 도입은 장면 한 줄이나 독자가 아는 전제로 연다. 결론 요약으로 열지 않는다.
6. 제목 — 이 분야에서 잘되는 제목 틀 세 가지와 예시. 검색어를 앞쪽에, 40~55자.
7. 분량 — 기둥별 분량. 분량보다 질문에 답했는지가 중요하다.
8. 하지 말 것 — AI 말투(“~에 대해 알아보겠습니다”, “결론적으로”), 과장, 근거 없는 단정

### 3-4. `brand/channels.md` — 인스타그램·쓰레드 규칙

```
# 인스타그램·쓰레드 제작 규칙

공통: (noEllipsis면) 말줄임표는 쓰지 않는다.

## 인스타그램: 저장하는 (분야) 카드
- 목표: 저장·공유. 톤.
- 시리즈 이름 3~5개 (예: "한 장 정리", "쉽게 말하면", "따라 해 보기")
- 캐러셀 8~10장.
(아래 kind 표를 그대로 쓰되 compare의 라벨을 이 분야에 맞게 정한다)
| kind | 역할 | 글자 수 |
| cover | 큰 질문이나 숫자 하나로 멈춰 세우기 | 제목 20자, 부제 30자 |
| point | 한 장에 한 메시지 | 제목 22자, 본문 90자 |
| stat | 숫자 하나를 크게 + 해석 한 줄 | 숫자 12자, 본문 60자 |
| compare | 독자가 아는 것에 빗대기 (라벨: 예 "쉽게 말하면") | 제목 22자, 본문 90자 |
| summary | 세 줄 요약 | 줄당 30자 |
| outro | 캐릭터 한마디 + "저장해 두세요" + 팔로우 안내 | 60자 |
- 캡션: 첫 줄 훅 → 핵심 세 줄 → 질문 하나 → 해시태그 5개 이하(이 분야에서 실제로 쓰는 태그 예시)
- 이모지는 캡션에 최대 2개, 카드에는 쓰지 않는다.

## 쓰레드: (분야) 이야기 친구
- 목표: 답글·대화. 톤은 블로그보다 가볍게. 한 글 450자 이내.
| format | 예시 틀 |  (이 분야에 맞는 형식 4~5개. question, term(용어 한 입), compare(쉽게 말하면)는 꼭 넣는다)
- 블로그 요약 타래 5개: 1번 훅, 2~4번 핵심, 5번 결론과 `{{BLOG_URL}}`.
- 단독 글 2~3개.
```

### 3-5. `brand/rules.md` — 리서치와 저작권 규칙

```
# 리서치와 저작권 규칙

모든 스킬이 지킨다. 도구는 WebSearch와 WebFetch만 쓴다.

## 리서치 순서
1. 주제와 사용자의 한 줄 관점으로 글이 답할 질문 3~5개를 정한다.
2. 질문마다 한국어와 영어로 검색한다. (이 분야에서 원문이 영어인 경우가 많으면 영어 원문 우선)
3. 필요한 페이지만 열어 사실, 날짜, 수치를 짧게 메모한다. 문장은 옮기지 않는다.
4. 수치와 핵심 사실은 서로 다른 출처 두 곳에서 교차 확인한다. 한 곳뿐이면 `one_source`, 못 찾으면 `unverified`. 수치마다 기준 시점(`as_of`).
5. 과거 비교 사례 2~3개와 "쉽게 말하면" 비유 후보 2~3개를 찾는다.
6. 블로그에 넣을 미디어 후보를 찾는다(아래 표).
7. 결과를 `brief.json`에 저장한다. 초안은 이 파일만 근거로 쓴다.

## 우선 출처
(1장에서 찾은 출처를 표로: 분야 | 출처 | 무엇을 확인할 때)

## 미디어 후보 (저작권 기준)
| 종류(kind) | 찾는 곳 | 쓰는 법 |
| youtube | 공식 채널 영상 | 링크 삽입. 영상 파일을 받지 않는다 |
| social | 공식 계정 게시물 | 링크 카드로 삽입 |
| photo | 위키미디어 커먼즈 자유 라이선스 사진(파일 페이지 주소 commons.wikimedia.org/wiki/File:…) | 프로그램이 받아 표지와 블로그에 쓰고 저작자 표기를 붙인다 |
| chart | 리서치한 수치 | 프로그램이 도표로 만든다 |
(이 분야에서 쓰면 안 되는 이미지 출처를 한 줄로)

## 금지
- 네이버 검색 API를 쓰지 않는다(약관이 AI 입력을 금지).
- 연합뉴스 기사 원문을 읽어 요약·재작성하지 않는다(저작권규약이 AI 이용을 금지).
- 기사 문장을 옮기거나 외국 기사를 번역해 옮기지 않는다. 직접 인용은 짧은 발언 한 문장까지만, 출처와 함께.
- 유료 기사는 공개된 부분만 쓴다.
- (1장에서 찾은 이 분야의 위험한 표현과 금지 출처)
```

## 4. 마무리

- `brand/pillars.json`은 유효한 JSON 배열인지 다시 읽어 확인한다.
- `brand/feedback.md`와 `brand/corpus/`는 고치지 않는다.
- 마지막 응답에는 만든 파일 경로만 적는다.
